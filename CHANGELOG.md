# Changelog

All notable changes to this project are documented here. Format follows [Keep a Changelog](https://keepachangelog.com/en/1.0.0/).

## [Unreleased]

### Added

- Added a one-time 14-day Pro trial with no card required. New business owners start it automatically on their first active business, and eligible existing Free businesses can start it from Billing. When it ends, the business returns to Free with its data retained.
- The full-local Docker stack now includes Redis behind an Upstash-compatible REST proxy. The app keeps using `@upstash/redis`, so cache, quota, cooldown, and rate-limit behavior can be exercised locally without a hosted Redis database.
- Rebuilt business analytics as four tabs — Overview, Performance, Operations, and Team — with fresh KPI, funnel, trend, money, attention, usage, timing, cohort, benchmark, and member-workload sections. Free plans see a fixed last-30-days Overview with real numbers; Pro plans unlock 7/30/90-day and 12-month/custom ranges plus Performance and Operations; Business plans add all-time history and team analytics. Locked tabs show static previews and their premium queries never run.
- Rebuilt analytics CSV export with summary and daily-series scopes, and re-resolve the date range and plan entitlement on the server so export cannot bypass the picker's range cap.
- Added goals, tracking annotations, and scheduled reports to the analytics reports surface, including a recipient cap of one for Pro and five for Business.

### Changed

- Pricing now uses fixed local prices in USD, PHP, GBP, CAD, AUD, EUR, NZD, SGD, AED, INR, and ZAR instead of USD-only checkout. The marketing pricing page detects the visitor's country from Vercel's geo header, and Polar products must carry a price in every supported currency. Annual prices remain exactly ten times the monthly price.
- Rebalanced plan packaging: Free now covers the complete inquiry → quote → invoice → manual payment loop with two live services and 20 Requo email sends per month; Pro includes 10 live services; Business keeps 5 seats, adds unlimited live services, and remains the only plan with audit logs. Marketing copy, in-app plan selection, and machine-readable pricing now share the canonical plan catalog.
- Core record exports are ungated on every plan: inquiries, quotes, and invoices download as CSV, PDF, or PNG. Custom workflow recipe edits and member invite acceptance now resolve the effective subscription plan, so an expired trial or downgrade cannot leave a stale cached plan granting paid access. Customer history is no longer described as a Pro feature.
- The AI router is now free-tier-first, with NVIDIA NIM as a production exception requiring NVIDIA AI Enterprise. Every routed model must resolve to an entry in `lib/ai/catalog.ts`; routing profiles are the only selection path (the unused pinned/manual override path was removed), and a model at or above 100% of any modelled quota is dropped from selection (80% only deprioritizes). Daily provider refusals cool the shared request or neuron bucket, and the assistant now distinguishes "no provider configured" from "all free capacity exhausted".
- The service editor surfaces the server's rules before the owner submits: publishing is owner-only, an unpublished service cannot be made the default, and the danger zone disables archiving and deleting with the reason. The two public `public_inquiry_enabled` flags (business-level and service-level) are now enforced consistently on the public inquiry pages.
- The database now enforces at most one default service per business with a partial unique index, and the plan's custom-field allowance is applied when a service's intake form is saved, so a crafted request cannot persist fields the plan does not include.
- The integration test suite runs its files sequentially so the end-of-run residue check is deterministic instead of flagging whichever file happened to still be running.

- Quote money is now derived on the server. The editor sends the owner's raw discount and tax intent (value plus amount/percentage) and the server computes the amounts from the submitted line items, instead of the browser shipping cents it calculated itself.
- The Owner Assistant's `create_quote` tool no longer accepts a price. It creates the line items unpriced and the owner prices them from the saved library or by hand; sending a quote with unpriced lines is still refused. The `send_quote` confirmation now shows the amount and is bound to the quote it approved, so a quote edited after you approve it is not sent silently.
- Quote cache invalidation now pairs `updateTag` with `revalidateTag` on every write, so a quote that the customer just accepted stops showing as "sent" on the dashboard.
- The quote CSV export is capped like the inquiry export and rejects an invalid date range instead of silently widening it.
- The quote feature's semantic surfaces use the `--warning` / `--success` / `--destructive` tokens instead of raw amber/emerald/red utilities.

- Tidied the analytics card layout: every card in a row shares one height, a plot fills its card, and the table view scrolls inside the card so switching between Chart and Table never blows the card up. The desktop toolbar is a bare control row instead of a boxed panel, switches use a plain thumb without the inset chip, the "Live" section headers are gone, the attention list is iconed by the kind of work it points at (inquiry, quote, follow-up, with the sidebar's inbox for inquiries), stat dividers connect through every row, the empty bar track is a visible grey instead of near-black, the service name lost its arrow, and the AI impact card now sets its four stats above the win-rate and readiness bars.
- The analytics aging list colours a bucket by its age rather than by its position among the buckets that have something in them, so a 90-day bucket stays danger-red even when every younger bucket is empty. The funnel's first stage now carries a caption, so every row in the funnel is the same height.
- Redesigned the whole analytics page around one calm, symmetrical layout: a centred 1280px container, a 12-column grid with 16px gaps, 32px between sections, and rows that only ever split 12, 6/6, 4/4/4, or 3/3/3/3 (the KPI strip is six 2-column tiles). Every card now shares one anatomy — title with an optional definition tooltip on the left, a Chart | Table toggle or "View all" on the right, one-line description, body, optional summary footer — and stats inside a card are separated by 1px dividers instead of nested bordered tiles.
- Rebuilt the analytics vocabulary as reusable primitives: `Stat`, `DeltaBadge`, `BarList` (the single horizontal-bar primitive behind funnels, aging, sources, win rate, and usage), `Funnel` (one hue, fading by stage), `AgingList` (accent → warning → danger), `Donut`, `DataTable`, `AttentionList`, `UsageMeter`, `EmptyState`, and one formatter module for currency, percent, duration, and compact numbers.
- Redrew every chart: unsmoothed lines for sparse counts, a soft area fill on the primary series only, the previous period as a 1px dashed neutral line, dots on hover, a shared compact tooltip, 3–4 horizontal gridlines and no axis lines, and a domain taken from the data instead of a fixed 0–4 scale. Revenue is rounded-top bars with the average accepted deal as a thin line.
- Regrouped the analytics tabs into sections: Overview (KPI strip, activity and revenue trends, funnel, quote outcomes) and Live (attention, receivables, plan usage) on the Overview tab; Performance, Audience, and Live on the Performance tab. Acquisition trend is now the Traffic tab of Activity, Campaigns is the Campaigns tab of Traffic sources, and Open quote aging plus Expiring within 7 days are one Open quote backlog card.
- Added the analytics data-visualization tokens (`--chart-series-*`, `--chart-grid`, `--chart-track`, `--chart-tooltip-*`, `--analytics-sparkline-height`) and documented them, with the chart and card rules, in `DESIGN.md`.
- README screenshots are now captured in native Windows Chrome at 2x by `npm run screenshots` (scripts/marketing/capture-readme-screenshots.mjs), so the images render with the same font rasterisation as the landing walkthrough recording; the Playwright capture stays available as `npm run screenshots:fallback`.

- Renamed the analytics entitlements from `analyticsConversion` and `analyticsWorkflow` to `analyticsPerformance` and `analyticsOperations`, and added `analyticsTeam` for Business-only team analytics.

- Simplified local development to two setups: cloud Supabase (`.env.local` + `npm run dev`) and full local (Supabase CLI + `npm run dev:docker`). Added `npm run db:local:setup` (migrations + demo seed + local realtime publication/policies), kept ngrok optional through `npm run dev:tunnel` and `npm run dev:docker:tunnel`, removed the local-Postgres-only hybrid path (compose `db` service, native flow docs), made `db:seed` refuse non-local databases, and standardized script/test env loading on `.env.local` then `.env`.
- Rebuilt the marketing hero dashboard preview as a static, pixel-accurate recreation of the real `/home` dashboard at a canonical 1440px desktop reference — real sidebar, topbar, assistant composer, stat cards, and priority queue — replacing the outdated mock, including the hero frame's new 1440:725 crop.
- The marketing hero preview now plays a recorded product walkthrough over that static recreation — autoplaying once in view, pausing off-screen and on hidden tabs, with a hover play/pause control and the static stage as the reduced-motion, unsupported-codec, and no-JavaScript fallback.
- Landing cards — feature previews, workflow steps, why-Requo graphics, and the hero frame — now render flat, with their elevation shadows removed.
- The landing page's "How it works" section is now an auto-advancing stepper: the stage shows the active step's preview while that step's bar fills in primary over five seconds and hands the cycle on to the next column, primary eyebrow labels and single-line titles keep the four columns even, inactive columns keep full-contrast copy (only the label and title tone soften) instead of dimming, clicking a column restarts its bar, and reduced motion keeps the manual stepper with no cycle.

### Removed

- Removed Cerebras and Mistral from AI routing, environment variables, the admin surface, tests, and legal disclosures. Cerebras' free allocation is expiring trial credit that requires a payment method, and Mistral is no longer part of Requo's provider set. Removed the retired Gemini 2.5 identifiers in favour of the current free-tier Gemini models.
- Removed the analytics AI narrative summary card; the rebuilt tabs present the same period data directly.

### Fixed

- Admin authorization is now database-authoritative. `requireAdminUser()` always re-reads `user.role` and `user.banned` instead of trusting the cached `admin` role in Better Auth's cookie cache, so a demoted or banned admin is refused on the next admin operation; demotion now also deletes the target's sessions, matching suspension. The proxy's cookie-derived gate remains an early rejection only.
- Billing was hardened end to end: subscriptions are business-scoped, Polar webhooks claim and finalize events atomically (including retries and stale claims), checkout and portal mutations are owner-only while other members can view billing read-only, and plan entitlements resolve from the subscription row instead of the denormalized cache. The runtime is pinned to Node 24 for the current Polar adapters.

- The AI features were reviewed end to end and the defects are fixed. The full findings and their resolutions are in [the AI features review](docs/reviews/ai-features-review.md). The ones that changed user-visible behaviour:

  - A quote drafted with AI could be sent without the owner confirming a suggested price. The editor submitted the AI readiness and the generation reference, but the save action never read them, so the columns were always written as `NULL` and the "suggested pricing needs confirmation" gate could never fire. The readiness is now recomputed on the server from the provenance that is actually persisted, and the editor keeps that provenance on every line.
  - A percentage discount was persisted as an absolute amount. The editor's discount type was discarded on the way in, so a 10 % discount on a $1,000 quote became $10 and the customer was emailed $990. The owner's intent — amount or percentage — now reaches the server, which derives both amounts from the submitted line items.
  - A manual knowledge entry replaced its own title with the body text, and any entry longer than 200 characters could not be saved at all.
  - The Owner Assistant could write to a plan-locked business, and the public Agent could file an inquiry against a service the business had taken offline or against a business that had turned intake off.
  - The AI agent settings were saved to whichever business the active-business cookie pointed at, not the business in the address bar.
  - The monthly AI credit pool was a cached read on every AI surface, so concurrent requests all passed the same stale total. The Agent, the Assistant, the quote draft, the auto-draft job and the file importer now reserve a credit before the provider call and settle it with the real token usage; a failed turn is charged for what it spent.
  - The router recorded the real token usage and then applied its correction on top of it, so the per-minute counter could go negative and a saturated provider looked idle to the capacity selector.
  - Every customer-supplied value now reaches the quote-draft model inside one untrusted-content fence whose closing tag cannot be written from the inside, the customer's own revision request no longer outranks the rest of the inquiry, and an exact price match takes its quantity from the priced candidate rather than from the model.
  - The public Agent's rate limits were keyed on a User-Agent the caller controls, so rotating a header defeated all of them; its per-business session allowance counted conversations that never happened; "Retry response" always failed; and "Stop generating" did not cancel the provider call.
  - The Assistant's conversation history cache was keyed by business, so the next member to sign in on a shared browser was shown the previous member's conversations.
  - A quote email that went out before the state transition is no longer reported as a failed send, and the Assistant's staged confirmations now freeze the state they were approved against and expire.
  - The follow-up prompt no longer carries the customer's quote link, which is a bearer credential; Requo appends it to the finished message instead.
  - The file importer sanitises the uploaded document, validates the model's answer, reports prices as written and lets the server own the conversion to cents, and draws on the plan's AI credits instead of spending invisibly. It also checks the shared free-tier counters before each extraction attempt and records the request and real token spend, and the embedding service records its usage under `google:gemini-embedding-001`, so neither direct provider path is invisible to routing capacity.
  - The auto-draft job persists the quote it generates. It used to burn the business's AI credits on every qualified inquiry and throw the draft away.

- The Services feature no longer loses the owner's work or breaks its own public page. Saving a service page with a new slug, and deleting a service, ran their `redirect()` inside the action's own `try`, so the redirect was swallowed and the owner was told the save failed even though it had already been written. Both redirects now run outside the `try`, like the intake-form save already did.
- "Apply defaults" in the service editor now takes effect. The editor kept its drafts in local state and never re-read them from the server, so applying a business-type template replaced the stored form and page config while the editor kept showing — and the next save kept re-writing — the old values. The editor now re-seeds each tab's draft from the server when that tab's stored config changes, and tracks the two tabs separately so saving one never discards unsaved work in the other.
- The business default service can no longer be unpublished. The rule was only enforced by the publish toggle, so saving the service page could unpublish the default and 404 the business's shared `/inquire/<business>` link. Every write path now keeps the default published, and an unpublished service can no longer be promoted to default.
- The live-service plan limit is now enforced atomically and against the authoritative plan. The count-then-insert could be raced by two concurrent creates, and it read the denormalized `businesses.plan` cache while the limit message read the effective plan. The count now runs inside the write transaction under a per-business advisory lock and resolves the effective plan from the subscription.
- The service editor resolves the business from the route slug instead of the active-business cookie, so it cannot open another business's service under the current URL.
- Deleting the last active service is refused instead of leaving the business without a default and a working public inquiry page. Deleting a service that collected page-view analytics is refused too, so the history is not silently dropped.
- Slug allocation now retries on a unique-slug conflict instead of failing with a generic error, and the service editor resolves its target by the slug the action was bound to rather than a client-supplied id.
- Archived, locked, and trashed businesses no longer keep a working public AI chat and service hub — the public agent surfaces now apply the same business-lifecycle filter as the public inquiry pages.
- Customer-supplied inquiry text no longer reaches the quote-draft system prompt as instructions. It is sanitized and fenced as untrusted customer data, and the prompt states that instructions inside it must not be followed.
- The inquiry attachment bucket now has a storage-layer size and MIME limit, so an anonymous caller cannot use a signed upload URL to push an unbounded file into a private bucket.
- The services list no longer ships every service's full form and page configuration to the browser; the list payload carries only identity, visibility, and counts.
- The "Add field" control no longer dead-ends at the plan's custom-field limit, the danger zone explains up front why archiving or deleting is unavailable, and the service editor's "unsaved changes" bar no longer stays lit after a save that only trimmed whitespace.

- A draft invoice converted from an accepted quote can be edited again. The edit form submitted a placeholder line item while the discount came from the quote, so the "discount cannot exceed the subtotal" rule rejected every save and the invoice could never leave draft. A quote-linked invoice now keeps the quote's line items and totals — the server decides which rule applies, the form submits the stored snapshot, and only the customer-facing fields and the date order are validated for it.
- Requo email sends are counted for invoices, not just quotes. The invoice send activity row recorded no delivery method, so the shared send allowance never saw invoice emails and the server-side plan gate was inert for them. Both send paths now record the delivery method and the counter covers quotes and invoices; the allowance is renamed `requoDocumentEmailsPerDay` / `requoDocumentEmailsPerMonth` to match.
- The "Sent" invoice status filter no longer returns nothing. It was offered in the invoice list, the CSV export, and the admin console, but the effective status rewrites a sent invoice to "unpaid" once a payment or a due date applies, so the filter could never match a row. The filter vocabulary is now exactly the states the effective status produces.
- Voiding invoices in bulk can no longer strand a recorded payment. The bulk path checked the recorded payments outside the transaction and without a row lock, so a payment recorded at the same time could be left on an invoice that then got voided — and a voided invoice's payments can no longer be voided. The whole bulk void now runs in one transaction under the same row lock the payment path uses.
- An invoice void now records why. The void reason column could never be filled because the action was always called without one; voiding an invoice now requires a reason, the same rule payment voids follow.
- Invoice money is validated against the storage limit. A line total, subtotal, or total could pass the form and fail at the database with a range error instead of a field error; every derived total is now capped in the schema.
- The printed invoice shows a readable status instead of the raw enum, and the invoice preview labels the total as "Total" rather than "Balance due". A zero discount or tax row is hidden, matching the invoice email.
- The invoice and payment surfaces use one set of labels. The payment-method and void-reason maps were redeclared in four files with conflicting casing, so a receipt could read "Bank Transfer" while the table read "Bank transfer"; they now come from one home.
- The per-invoice balance is called "Balance due" everywhere, matching the domain term, instead of "Remaining balance" on the receipt, the payment detail, and the record-payment dialog.
- Removed the invoice feature's unreachable code: an unused `pdf-lib` invoice renderer and an unused invoice-overview query that nothing rendered.

- Automatic follow-ups are a paid capability again. The send mode was never checked against the plan, so a Free business could have Requo email its customers unattended, with no daily or monthly send budget on any plan. The entitlement is now enforced on the server when the follow-up is created or switched to automatic, re-checked at send time so a downgrade pauses the sequence, and the shared `autoFollowUpEmailsPerDay` / `autoFollowUpEmailsPerMonth` allowance now covers both the quote sequence and the follow-up path.
- A due date no longer lands on the wrong calendar day east of UTC+9. The due date was converted by shifting the hour but keeping the date, so a business in Sydney, Auckland or Kiritimati got a follow-up that was due a day later than the one they picked, and the "due today" badge disagreed with the board. Due dates, day buckets, list filters and the reschedule/snooze pickers are now all read in the business timezone, and a follow-up's due date is shown in that timezone too.
- Completing a follow-up twice no longer doubles the work. The transition was read and written without a row lock, so two concurrent completions could both clear the task, both log it and both spawn the next occurrence of a recurring series. Every interactive transition now locks the row and only writes when the follow-up is still pending.
- Bulk-completing recurring follow-ups no longer ends the series. The bulk path skipped the recurrence step, so clearing several rows at once silently stopped a repeating follow-up.
- A recurring follow-up that should end when its inquiry or quote reaches a terminal status now actually stops. The termination helper had no caller, so a won inquiry or a voided quote left the series pending and showing as overdue. It is now called from the inquiry status, archive and quote void/expiry paths.
- The follow-up reminder email no longer links to a 404. The link was built as `/b/{slug}/…`, but the dashboard lives at `/{slug}/…`, so every "Open Details" button in the reminder went nowhere.
- Automatic follow-up emails are branded and actionable again. They ignored the business's follow-up template and signature, never included the quote link, and were recorded as quote emails even for inquiries. A quote follow-up now uses the quote template with the public quote URL, an inquiry follow-up uses the branded layout and is recorded as an inquiry email.
- A follow-up that stays overdue no longer pushes a new in-app notification every single day. The job now raises the overdue notice at most once per business-local day.
- The AI-generated follow-up message is grounded in the tenant's own data and charges the shared AI credit pool. The endpoint used to take the customer name, business name and quote link straight from the browser; it now takes the follow-up id and loads the rest server-side, and a generated message draws on the same monthly allowance as every other AI surface.
- The follow-ups list no longer 500s on a malformed page number, and its search no longer treats `%` or `_` in the search term as a wildcard.
- A deleted follow-up no longer counts as pending work on the inquiry and quote lists, so the "work follow-up" next action no longer points at a task that was already removed.
- The reassign menu entry works. The dialog existed but its trigger was hidden and the menu item was permanently disabled, so a follow-up could never be handed to another team member.
- A follow-up can no longer be assigned to someone who is not a member of the business, and the assignee is validated on the server rather than trusted from the form.
- A follow-up can no longer be set to repeat forever by accident. Choosing "repeat N times" without a count is now refused instead of silently running unbounded, and a count is required alongside a repeat.
- A completion note that is too long is now reported instead of silently dropped, and a snooze time is read in the business timezone instead of the server's.
- A repeating automatic follow-up keeps repeating. The automatic send cleared the task without creating the next occurrence, so a "repeat every week" follow-up sent one email and stopped, even though the board still promised a repeat.
- An automatic follow-up is no longer marked as sent when nothing was sent. With no email provider configured, or with a sender address the provider rejects, the follow-up was quietly closed, the owner lost the task, and the business's automatic-send allowance was charged for mail that never left. The task now stays open until an email is actually delivered, and the quote follow-up sequence no longer burns an attempt either.
- Two automatic follow-ups on the same quote now both reach the customer. The email idempotency key was scoped to the quote, so the second one was swallowed by the outbox while the task was still closed as sent.
- The follow-up due date is now shown in the business timezone everywhere — the board, the history sheet, the dashboard priority queue and the activity timeline — instead of the server's timezone.

- Editing a saved quote no longer re-prices it. The editor read the quote's absolute tax back as a percentage, so re-opening and saving a draft multiplied the tax by the subtotal — an $80 tax on a $1,000 quote became $800 and the total went from $1,080 to $1,800.
- A zero-priced line item can be saved again. A blank price became `NaN` and was rejected, so the AI "needs pricing" workflow could not be saved at all. A quote with unpriced lines is still refused when sending.
- The customer email now goes out only after the send gates pass. A quote the server considered unsendable could still be emailed, leaving the customer with a link to a draft that 404s.
- Re-sending a revised quote delivers the email again. The email idempotency key did not pin the quote version, so the second send was silently swallowed by the outbox.
- The AI quote generator produces priced line items again. The output filter was redacting the model's `matchType` and `unitPriceInCents` JSON keys, so every draft came back unpriced.
- A quote can no longer end up declined while holding a signed acceptance record: the public response is a conditional transition on a locked row.
- An archived quote is no longer publicly readable or acceptable, and an expired quote can no longer be revived by a revision request.
- The quote auto-follow-up stop is scoped to the business. Any member of any workspace could stop another business's customer follow-up sequence by posting its quote id.
- The public quote page no longer ships the business plan tier, internal entity ids, or the acceptance record's audit fields to the browser, and the public quote bundle no longer carries a Node crypto polyfill.
- The public quote rate limits gained the per-IP and per-scope ceilings the inquiry intake already had, and the rate-limit ledger no longer stores the raw bearer token.
- The quote jobs now evaluate their day windows in the business's own timezone, and the auto follow-up no longer chases a quote the customer can no longer accept.
- The admin quote console filters and badges on the effective status, so the "Expired" filter returns the right set and archived quotes are visible.
- The quote PDF, print document, and public quote page now show the tax line and its label.
- Quote archive and restore now write an audit record, and saving a quote keeps the line-item ids so the customer's per-item revision comments still resolve.

- The live fallback for un-rolled analytics days no longer drops most of a day's numbers. The per-day metrics used to be joined with a chain of `full outer join`s that all anchored on the form-view date, so a day without a form view was split across several rows and only one of them survived — quotes sent, quotes accepted, and revenue won read as zero. Every metric now joins onto one date spine, so a day always lands on a single row with all of its numbers.
- The live fallback now reads only the days the rollup has not processed, instead of re-reading the whole window on every uncached load and discarding what the rollup already had.
- The daily rollup and the live read path count the same things now: visitors who opened a service form, form views that belong to a form, and live (not deleted) inquiries and quotes. A window that mixes rolled-up and live days no longer plots two definitions of "visitors" on one line. `npm run db:backfill-rollups -- --from=YYYY-MM-DD --to=YYYY-MM-DD` recomputes the days already rolled up.
- "Avg won deal" divides the won value by the quotes won in the period — one population, not a value counted by acceptance date divided by a count counted by send date. The KPI now matches the "Average accepted deal" in the CSV export.
- "First response" no longer averages over answered inquiries only, which made the number look better as the service got worse. The tile now reports how many of the period's inquiries got a reply, and only a real reply (a note, a status change, a quote) counts as one.
- Analytics stat grids follow the card they live in rather than the viewport, so a half-width card no longer squeezes two stats into a narrow column. The container layout is now the default, which keeps a new card from half-applying the fix.
- Analytics trend charts no longer read as flat zero lines when the daily rollup job has not processed the window yet (a seeded workspace, a range that predates the job, a fresh install). The series builder now falls back to the live source tables for the days the rollup is missing, so the trend shows the activity that actually happened.
- The Top customers card now shows won value as currency ("$1,750") instead of the raw cent amount ("175,000").
- Both win-rate definitions now carry their formula in a tooltip: accepted ÷ decided quotes on the KPI tile and the breakdown card, accepted ÷ quotes sent on the service performance table.
- The demo seed now records each inquiry's form view on the same day as the inquiry and adds visitors who browsed the form without inquiring, so the visitor → inquiry funnel reads as a real rate instead of exceeding 100%.
- The analytics funnel states the counts ("9 from 7 visitors") when a stage sits above the one before it, instead of a conversion above 100% that reads as a broken number.
- The dashboard greeting no longer causes a hydration mismatch: the time of day is resolved on the client, so the server's copy and the viewer's copy no longer disagree.
- The mobile top bar's page title is no longer a second `<h1>` on the page — the page keeps the single document heading.
- The model-catalog drift check now loads `.env.local`, so provider keys configured there are compared instead of reported as missing; `CATALOG_DRIFT_ALLOW_MISSING` is documented in `.env.example` for local runs without keys.
- The demo seed no longer fails when it runs over an existing database: a quote that already carries a commercial schedule reuses that schedule instead of orphaning its items.
- The public inquiry browser tests no longer fill the service-category field, which is owned by the service form and is no longer a customer-facing field.
- Dashboard notifications now subscribe with a fresh realtime channel topic on every mount, so an in-flight channel removal can no longer trigger the "cannot add `postgres_changes` callbacks after `subscribe()`" runtime error.
- The inquiry surface resolves the business plan from the subscription instead of the denormalized `businesses.plan` cache, and every subscription status change now rewrites that cache in the same transaction as the subscription row. A business whose subscription lapsed no longer keeps paid inquiry features, and the public form no longer silently discards the answers a visitor gave to fields the plan no longer allows.
- The inquiry acknowledgment email escapes visitor-supplied text. It was the only email template that did not, so a visitor could inject arbitrary HTML into a message sent from the platform's sending domain to an address they chose.
- CSV exports neutralize leading formula characters, so a customer-submitted `=HYPERLINK(...)` in any exported field is treated as text instead of evaluating when the owner opens the file.
- "Select all" on the inquiry list now selects the inquiries that match the current filters, up to the 50-item cap, instead of the handful that happened to be cached. The quotes and invoices bulk bars say "Select all on loaded pages", which is what they actually do.
- The 25 MB and 50 MB plan attachment limits are now reachable. The file used to travel inside the inquiry server action, and a Vercel Function rejects any request body above 4.5 MB with `413 FUNCTION_PAYLOAD_TOO_LARGE` before Next.js ever sees it — so a paid plan's attachment could never be sent at all. Attachments now upload straight to storage through a signed URL, and the inquiry carries a signed upload token that binds the file to the business. The server still checks the plan limit, the file type, and that the uploaded object really exists.
- A visitor who uploaded a file and then abandoned the form left the object in storage forever. A daily sweep now removes uploads that were never attached to an inquiry.
- A deleted inquiry's attachments are no longer downloadable, and the attachment download route is rate limited per business.
- Duplicate detection matches a customer's email address case-insensitively, so the same person submitting `Jane@Example.com` and `jane@example.com` is flagged rather than silently missed.
- The admin inquiry console shows the same status the business sees — `waiting` after 48 hours, `overdue` once the deadline passes — and separates archived inquiries instead of listing them with a stale pipeline status.
- The inquiry status confirmation now reports the status on the badge, so choosing "New" on an inquiry that reads as "Overdue" no longer answers "already New".
